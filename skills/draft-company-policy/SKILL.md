## Drafting Instructions

**Generate a clear, actionable company policy following these guidelines:**

### 1. Document Header
Include:
- Company name
- Policy name with "Policy" suffix
- Policy number
- Effective date
- Policy owner (department/role)
- Approver (title like CEO, CHRO)

### 2. Purpose Section
In 2-4 sentences, explain:
- Why this policy exists (reference problems to solve)
- What it aims to achieve (reference desired outcomes)
- How it supports company values or compliance obligations

### 3. Scope Section
Clearly state:
- Who this policy applies to (based on user selections)
- What situations/activities/behaviors are covered
- What is NOT covered (exclusions if helpful)

### 4. Definitions Section (if needed)
If policy uses specific terms, define them in a simple table. Only include if terms need clarity.

### 5. Policy Statement
This is the heart of the policy. Organize by subtopics with numbered subsections (5.1, 5.2, etc.):
- State clear requirements using "must," "must not," or "should"
- Be specific, not vague
- Provide examples if helpful
- Keep each requirement to 1-2 sentences
- Use clear, direct language
- Avoid legal jargon
- Address the "what to prevent" items from user input

### 6. Procedures Section (if applicable)
If policy requires specific processes, include step-by-step instructions. Only include if policy requires procedural compliance (e.g., how to request remote work, how to classify data).

### 7. Roles & Responsibilities
Create a table showing what each role must do:
- Employees
- Managers
- Policy owner
- HR/Legal (if applicable)

### 8. Exceptions
State how exceptions are handled:
- Who can request an exception
- Who approves exceptions (use info provided)
- Process for requesting
- Whether exceptions are documented and time-limited

### 9. Violations & Consequences
Based on consequence levels selected, state: "Violations of this policy may result in disciplinary action up to and including termination of employment."

List the selected consequence levels and include reporting process.

### 10. Related Policies
List any related policies mentioned in user input.

### 11. Revision History
Create simple table with: Version, Date, Author, Changes
Initial entry: Version 1.0 with effective date and policy owner as author

### 12. Review Schedule
State: "This policy will be reviewed annually by [Policy Owner] and updated as necessary."

**Output Guidelines:**
- Write in clear, plain language (8th-grade reading level)
- Be prescriptive, not aspirational (use "must" not "should strive to")
- Keep it concise (2-5 pages typical)
- Use active voice
- Provide specific examples for complex requirements
- Make it actionable (employees should understand exactly what to do)
- Avoid legal jargon unless necessary for compliance
- Format with clear headings and numbering
- If information is missing, use **[PLACEHOLDER]** and note what's needed
